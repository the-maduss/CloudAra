# ۵. محیط و دفتر پروژه — Environment & Workbook

[بازگشت به معرفی پروژه](../README.md)

## هدف

ایجاد یک محل مرکزی برای نگهداری نسخه معتبر مستندات، تصمیم‌ها و خروجی‌های پروژه؛ همان Project Workbook معرفی‌شده در اسلاید.

## ابزارها

| ابزار / محیط | کاربرد | وضعیت در این مرحله |
|---|---|---|
| مخزن GitHub با نام CloudAra | محل مرکزی و تاریخچه تغییرات | مورد استفاده |
| Markdown و پوشه docs | نگارش و دسته‌بندی اسناد | مورد استفاده |
| GitHub Issues | پرسش‌ها، وظایف و گزارش‌ها | روش پیشنهادی برای ادامه |
| Pull Requests | بررسی تغییرات بعدی | روش پیشنهادی برای ادامه |
| محیط آزمایشی با داده ساختگی | نمایش نمونه محصول در مراحل بعد | برنامه‌ریزی‌شده؛ ایجاد نشده |

## ساختار فعلی دفتر پروژه

| مسیر | محتوا |
|---|---|
| README.md | معرفی، فرض‌ها، منابع و فهرست اسناد |
| docs/01-initiation-team.md | تیم آغاز پروژه |

| docs/03-initiation-plan.md | برنامه شروع |
| docs/04-management-procedures.md | قواعد مدیریت |
| docs/05-environment-workbook.md | محیط و دفتر پروژه |

صورت‌جلسه‌ها و تصمیم‌های بعدی، در صورت ایجاد، به‌صورت فایل تاریخ‌دار در پوشه‌های docs/meetings و docs/decisions نگهداری می‌شوند. این پوشه‌ها در نسخه آغازین ضروری نیستند و هنوز محتوایی برای آن‌ها ثبت نشده است.

## قواعد نگهداری

- نام فایل‌ها کوتاه، انگلیسی و دارای شماره باشد؛ متن آموزشی فارسی نوشته شود.
- README نقطه ورود به آخرین اسناد معتبر باشد.
- هر تغییر با پیام Commit معنادار ذخیره شود.
- تصمیم مهم، دلیل و پیوند به سند مرتبط داشته باشد.
- اسناد تأییدشده در آینده با برچسب نسخه مشخص شوند؛ نسخه ۱٫۰ فعلی نسخه مستندات است، نه تأیید رسمی مشتری.
- فقط مطالب قابل انتشار در مخزن عمومی ثبت شوند؛ اطلاعات ورود، کلید API، داده واقعی مشتری و مکاتبات خصوصی در آن قرار نگیرند.

## معیار پایان فعالیت

هر شش سند از README قابل دسترسی باشند، تاریخچه تغییرات در GitHub ثبت شود و محل نگهداری خروجی‌های آینده مشخص باشد.
